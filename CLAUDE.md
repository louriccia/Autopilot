# Autopilot - Discord Bot

Discord.js v14 bot for the Star Wars: Galactic Racer server. Its command/interaction handler skeleton is borrowed from Botto (`../Botto`); nothing else from Botto is carried over.

## Tech Stack

- **Runtime**: Node.js 18+
- **Framework**: discord.js v14
- **Deployment**: Heroku app `autopilot-swgr` (same account as Botto's `swe1rbotto`), one Basic `worker` dyno from the Procfile (no HTTP surface, unlike Botto's `web` dyno; web stays at 0). The repo is public (MIT) without the game content: assets/, src/data/swgr/ and src/data/flavor/welcome.js are git-ignored and were removed from history, so deploy with `npm run ship` (src/scripts/deploy-heroku.js: HEAD plus that content as a one-off commit, force-pushed to heroku main), never `git push heroku main`; settings are Heroku config vars mirroring .env, with `TESTING=false` and no `TESTING_GUILDS` / `TEST_CHANNEL_ID`. Logs: `heroku logs -a autopilot-swgr --tail`.

## Project Structure

```
config.js             # testing flag + clientId
src/
  bot.js              # Entry point: loads handlers, dispatches interactions, error reporting
  commands/           # One slash command per file: { data: SlashCommandBuilder, execute, autocomplete? }
  interactions/       # Component/modal handlers: { name, execute }, routed by customId prefix
  respond.js          # navigate(): redraws the card in place for whoever used it (anyone can move any card; a plain announcement's View board, not being a Components V2 card, posts the board as a public reply)
  firebase.js         # Realtime Database (Firebase project autopilot-swgr) via firebase-admin; `database` is null without FIREBASE_* in .env
  feeds/              # Announcement feeds polled on a timer: steam-build (new Steam builds, via steam-user's anonymous
                      #   product info), steam-news (official announcements; patch notes in full), youtube (channel RSS),
                      #   twitch (live streams in the game's category, Helix API).
                      #   State (what's been posted) in the database at feeds/<name> (data/state/feeds.json, git-ignored, when
                      #   there's no database); a feed's first run only primes it
  swgr/data.js        # Lookups and autocomplete search over the game data
  swgr/search.js      # /search index: one entry per searchable kind (items, label, keywords, page)
  swgr/pages.js       # Page builders (arcade, track, planet, scenario, racer style, part, ability, vehicle, favor, rival, character, mystery, status effect, backer, tale, livery): Components V2 payloads
  data/swgr/          # GENERATED by tools/import_swgr.py — planets, tracks, arcade events, scenarios, styles, parts, abilities, vehicles, favors, rivals, racers (character cards), mysteries, statuses, sponsors, tales, liveries
  data/community/     # HAND-MAINTAINED data from outside the game files (ability-values.json: ability values the game files leave out, shown as ? until filled)
  data/discord/       # Guild and channel IDs (from .env)
  data/flavor/        # Flavor text
  scripts/deploy-commands.js  # Register slash commands (--list | --global | --guild | --clear-guild)
  scripts/preview-feeds.js    # Post each feed's latest item to TEST_CHANNEL_ID to see the cards
  templates/          # Starting points for new commands and interactions (not loaded)
assets/               # GENERATED art (WebP), uploaded as attachments and referenced via attachment://
tools/import_swgr.py  # Builds data/swgr + assets from ../swgr-datamine/out and E:/SWGR_Export (Python + Pillow)
tools/preview/        # PROOF OF CONCEPT, customised speeder previews: render_passes.py (Blender: each part alone, black/white paint per finish, livery position, depth -> assets/passes/<Class>), compose.py (any parts / palette / pattern / patina from those passes, with contact shadows), check.py (vs a full render)
```

## Game data

The game is STAR WARS Galactic Racer (codename "Griffin"; planets have dog codenames: Mastiff=Jakku, Dalmatian=Lantaana, Corgi=Ando Prime, Husky=Sentinel I, Spaniel=Crait, Whippet=Derven Acos, Beagle=Tatooine). Never hand-edit `src/data/swgr/` or `assets/` — change the importer and re-run it. Both are git-ignored (game content stays out of the public repo); a fresh clone needs the datamine to generate them. Ids are slugs of the display name (`the-giants-graveyard`).

## Key Concepts

- **Handler context**: every `execute` receives `{ client, interaction, member_id, member_name, member_avatar }`; interaction handlers also get `args`.
- **customId routing**: `"<name>_<arg1>_<arg2>"` → `src/interactions/<handler with that name>` with `args = [arg1, arg2]`. Handler names must not contain `_`.
- **Guild switching**: `testing` (from `TESTING` in .env, or automatically when `USERNAME == 'louri'`) makes the bot answer only in `TEST_GUILD_ID` (plus `TESTING_GUILDS`); live, it answers everywhere except there. The local copy and the Heroku bot share one application, so never put a live server in the local `TESTING_GUILDS`: both would answer there.
- **Feeds**: post to PATCH_CHANNEL_ID (#news-and-media: Steam builds + announcements, and news articles) and VIDEO_CHANNEL_ID (YouTube; channels in YOUTUBE_CHANNELS, default the game's own) and STREAM_CHANNEL_ID (Twitch; needs TWITCH_ID / TWITCH_SECRET; streams announced at TWITCH_MIN_VIEWERS, default 100, in TWITCH_LANGUAGES, default en, once per streamer per 8 hours, as Botto-style embeds; recognized streamers (/streamer, database streamers/) skip the minimum and get the big card). COMMUNITY_CHANNEL_ID (#community) gets src/feeds/community.js, posted as bare links so Discord builds the previews (videos and clips play inline), English only where the source says: r/StarWarsGalacticRacer's top 3 of the day (its RSS: Reddit's API needs approval and the feed has no scores), YouTube videos about the game from other channels reaching 1,000 views within 2 days (a search costs 100 quota units; "get it free" scam titles skipped; declared language English, else a Latin-script title) and Twitch clips of the game with 50+ views (in TWITCH_LANGUAGES); at most 5 per check. Bing News articles (US English) from the last 2 days are in the same module but post to PATCH_CHANNEL_ID, with the official announcements (Google News links only open through JavaScript, so Discord can't preview them). While testing, everything goes to TEST_CHANNEL_ID. A feed with no channel doesn't run. New feed = a module in src/feeds with { name, channel, every, check(seen, { preview }) } added to FEEDS.
- **Database**: Firebase Realtime Database `autopilot-swgr-default-rtdb` (project `autopilot-swgr`). The bot writes with the firebase-adminsdk service account, which bypasses rules; the rules (database.rules.json, `firebase deploy --only database`) let anyone read times, staff, profiles, balances, credits, backers, bounties, feedback and rivals (for the community website; DATABASE.md is its guide, keep it current when those change) and lock out everything else, writes included. profiles/<id> { name, avatar } is kept by src/profiles.js (live bot only, at start and hourly). Document each top-level path in src/firebase.js.
- **Errors**: `reportError()` in bot.js posts stack traces to `LOG_CHANNEL_ID` when live.
- **Intents**: `Guilds`, plus `GuildMembers` (privileged: Server Members Intent in the Developer Portal) for join messages, `GuildMessages` + `MessageContent` (privileged: Message Content Intent) for replays, and `GuildMessageReactions` for ⏱️ reactions. Add more (and enable privileged ones in the Developer Portal) when a feature needs them; a privileged intent that isn't enabled stops the bot logging in.
- **Times and feedback** (src/records.js; src/submit.js saves a time for both the card's form and /submit, updating the details of an exact repeat instead of saving it twice; interactions/time.js and rate.js): arcade and scenario cards carry Submit (the game's stopwatch icon) and three thumbs buttons, an icon-only bounty button (the target marker) beside the leaderboard, and a one-line build with an icon-only show/hide details button (a triangle pointing down or up; details_<kind>_<target>_<show|hide>; a redraw of the same card keeps it open or closed via pages.buildExpanded, any other card starts condensed). Everything is keyed by Discord id, never name. Leaderboards show each person's best; server managers, /submitter people and members of SUBMITTER_ROLE_IDS roles (Speedrun Archivist) can submit for others (a Racer picker in the form) and remove anyone's times (/times remove; everyone else only their own). Staff times (the developer's / publisher's own runs, by name, with their logo) live in the database at staff/ and are set with /times staff. A staff time linked to a Discord id makes that person staff (records.staffOf): their arcade runs, however submitted, become their staff time (when faster) instead of a community time. Pages read records' in-memory copy, so they stay synchronous. Leaderboards show the top 5 (place_1-10 emojis, times as bold code) plus the viewer's own best with the places just above and below it, and their rival's (marked with the rival emoji); on arcade boards a viewer with a time sees the medals still ahead of it and only the best one it beats (all three without a time); the viewer comes from src/viewer.js (AsyncLocalStorage set per interaction in bot.js; a card redrawn in place after a rating or a submission shows the view of whoever did it).
- **Progress** (src/progress.js, called from src/submit.js on every save): the submitter's private receipt (personal best, world record, bops = racers they passed, who each drop a place, first-time medals, place and gap to the next, rival gap, progression), and podium announcements to ANNOUNCE_CHANNEL_ID (#autopilot; TEST_CHANNEL_ID while testing) when a board with 5+ racers gets a new top-3 entrant, a move up within it, or a lowered record; no pings, a View board button. Imports and backfills pass announce: false.
- **Rivals** (/times rival, database rivals/): one declared rival each, shown on timesheets (head to head on shared events, the gap per event) and receipts, with the game's target marker as the `rival` emoji.
- **Credits** (src/credits.js; /credits, /bounty): the one currency, earned for progress, spent on bounties. Every change is a ledger entry (credits/<id>) and the balance (balances/<id>) moves only in a Firebase transaction. A save pays (credits.payRun from src/submit.js) for: first time on a board 100, personal best 50 + 10 per tenth (cap 500), each medal reached for the first time 100/200/400, bops 25 each (up to 5), passing your rival 150, and on boards with 5+ racers top 3 300 and world record 1,000; first time completing a category 500, all 50 main events 5,000; scaled by proof (video x1, screenshot x0.75, none x0.25). A board reaching 5 racers pays its top 3 once (fills/). Slower runs, repeats and staff earn nothing, except that a repeat bringing better proof (a video after a screenshot) tops the run up to the new rate (credits.upgradeProof). Bonuses are judged against the board as it is when the run is saved, not as it was on the run's date (no clawbacks, nothing gained by back-dating); a removed time takes back its run entry (records.onRemove). A first rating of a board pays 10. /credits balance shows a racer's balance and backer with a "Recent transactions" menu of their last 25 ledger entries (pages.ledgerSelect; picking one opens its board, interactions/ledger.js).
  Backers are the onboarding roles The Hutt / The Broker / The Pirate, counted after 24 hours held (backers/<id>, updated on GuildMemberUpdate): Hutt podium x1.5 but keeps 10% of the rest; Broker personal bests and medals x1.25 and no bounty fee; Pirate bops x2 and bounty winnings +25%, personal bests -25%. Standings sum what each side earned.
  Bounties (bounties/) go on an event or scenario (kind arcade | scenario), or on a cumulative leaderboard (kind aggregate, target 'main' for all 50 or a category id; won by a racer's total across its events, checked when one of its events gets a proven save; credits.aggregateEvents / bestOn / boardName). They're posted from a balance (at least 100) with /bounty post or a card's "Set a bounty" (announced publicly where posted, pages.bountyPosted; shown at the top of the board's leaderboard), anyone can add; the first saved run under the time with a screenshot or video wins the pot (funders can't), announced in ANNOUNCE_CHANNEL_ID; after 14 days they go back to their funders minus 5% (an hourly sweep in bot.js). No transfers between racers.
- **Spreadsheets** (src/sheets.js, /times export and import): export writes a CSV (ids and times as ="..." text so spreadsheets don't mangle them; once per 10 minutes per person). Import needs exactly the export's headers; a row with a saved entry_id corrects that time in place (any column) or removes it when its time and seconds are cleared, other rows are new times through src/submit.js (blank platforms stay blank). Racers match by discord_id, else username. Same rights as /times remove: your own, or anyone's for submitters. Failed rows come back as a CSV with the same headers.
- **Character cards** (/character, pages.characterInfo, data/swgr/racers.json): everyone selectable in multiplayer, Quick Race's 13 and Quick Podrace's 6 pilots, one card per name: the game doesn't tell the pilots' older selves (their Podracing Tour style) or Sebulba's campaign def apart, so those join the same card. Each multiplayer mode's racer style comes from the RacerDef's PvpRacerStyles. The card names the modes only when a character's style differs between them (the podracer pilots). Layout: the scenario named after them (tagline and tier beside a Scenario button; the scenario card links back with the character's button beside its planet line), then the style, its starting abilities, its speeders, the build's stats, then the favor; each beside a button to its card that names it, so no headings; no menu at the bottom but the character picker. Of the rivalry, only an Act III rival (after Tour 2) is mentioned. These are separate Pvp_Style_* assets with their own traits, not the campaign ranks. Quick Race / Quick Podrace also give the build (VehicleBuildOverride; podracer bars are its AuthoredBuildStats). Speeder buttons carry the model's manufacturer badge (vehicle.emoji, mfr_<Manufacturer>_<A|B>). Speeders: per class, the model and its customisation in the garage's tab order, Livery / Color / Patina (pattern / palette / patina, via racer_vehicles.csv). The garage leaves those options unlabelled, so they show as emojis: lv_<Class>_<pattern> as its garage tile (the ThumbnailOffsetExtent window of its SDF, turned a quarter anticlockwise) in the default palette (Dark Enigma), the pal_ palette tiles, and pat_ swatches the importer draws after the garage's tiles (the patina masks export blank). Style cards list the characters who race them (the owner, then any podracer pilot borrowing it in Podracing Tour) with buttons, not scenarios. characters.json is separate: headshot emojis for the whole cast.
- **Garage** (MVP; src/swgr/garage.js, preview.js, interactions/cust.js, /customize; a speeder's vehicle card is the garage on its stock model: /vehicle, /search, the class menus and character speeders open it there (garage.respond), with the model's description, manufacturer, Kit Points and unlock, and a menu of the characters and arcade events racing it; podracers, not customisable yet, keep pages.vehicleInfo): build a speeder from any kit's parts with a livery, color and patina, and see it. preview.js composes the image from tools/preview/render_passes.py's per-part passes in assets/passes/<Class>/ (each finish's black and white paint renders, so any color is black + color x (white - black); render_passes.py sets the vehicle materials from their own parameters instead of the datamine importer's world-prop path, which put a rusted-metal texture on every metal: painted metal, plastic, rubber, leather and fabric take their Base Colour / Metallic / Roughness Base, bare metals (Base Colour is the #FF0058 placeholder) and the engines' Heat metal get muted presets, glass a light tint of its Glass Colour; lit by Blender's interior HDRI; the pattern's SDF, copied by the importer to assets/liveries/sdf/, sampled at each pixel's livery UV: speeder patterns are laid out on the meshes' third UV map (UVMap.002 / TEXCOORD_2), like podracers', not projected top-down as the datamine's Blender importer does (checked against the garage: Ace02's teal band runs along the Speeder Bike's side panel edge only through UV2); parts stacked by depth with screen-space contact shadows). Only classes with passes rendered offer it (Speeder Bike so far). Three tabs, as the game labels them: Choose Model (a vehicle class menu, then any kit for every slot; "Custom" once a part differs; another class starts on its first model keeping color and patina), Edit Vehicle (a menu per slot), Edit Livery (Livery, Color 23 a page with its first and last options turning the page, wrapping, and Patina). All ten menus with their emojis on one card went over Discord's message size (413 / 500). The whole build is encoded in the custom ids (garage.encode: class, base kit, a kit per slot, livery, color, patina, color page, tab in base 36). Slots come from vehicles.json classes[].slots (out/vehicle_parts.json); patterns carry sdf + masks and patinas finish + body for it. Patinas: each is a square grid of finishes (Patinas/T_*: 0 paint, 105 rust, 255 bare steel; the All ones 4x4, Mix 8x8, Rust Steel Mix 16x16; the export left them blank, so the importer reads the texels from the raw package, SwgrDump raw .../Liveries/Patinas -> out/raw), and every vehicle mesh (a part's base and each panel) takes one cell from its PatinaUV (its StaticMesh's PatinaUserData; SwgrDump dump .../Customisation --match "^SM_"), written per pixel in each part's _patina pass: the nearest texel, column round((n - 1) x), row round((n - 1) y), checked panel by panel against the garage's Napaco D under Mix and Rust Steel Mix (render_passes.py --reference Goblin --view top --cam 0.3,-1,0.8,1.25 --patina-grid <id> renders it from the garage's angle) (the material only reads the result, a per-mesh custom primitive data CPD_PatinaType, so a mesh is never split). The livery is painted over whatever the cell says. A part whose socket moves with another slot's kit (only the bike's rear engine, on the front engine, at four heights) has a render per position (<kit>_<slot>@<group kit>, passes.json sockets). Passes are 768px; previews are composed on a worker thread (preview-worker.js, preview.renderAsync) so the 1.5-2.5 s of CPU per image never holds up other clicks; preview.js keeps decoded passes under PREVIEW_CACHE_MB (default 80: at 768px each is ~4.7 MB, and the Basic dyno has 512 MB). /customize picks its vehicle by autocomplete (36 speeders, past Discord's 25 choices), the person's saved builds first. Save (a star beside the tabs) keeps a build for whoever clicks (database garage/<id>/<build key>, at most 25; garage.buildKey is the code without page and tab); Choose Model then has a "Your saved builds" menu. Character speeders and arcade events (their customisation preset, arcade_events.csv Preset, read into arcade.json events[].livery) carry a Customize button opening that exact build (garage.openId, cust_build_<code>), and the garage links back: a stock build dressed exactly as a character's speeder or an event's shows their buttons under the image ("Raced as", garage.knownAs). The image is named speeder-<build key>.png, so a redraw that changes only the tab or colour page keeps the message's attachment instead of composing it again, and the last 40 composed images are kept in memory. Another class keeps the build: the classes list their models alike (the same manufacturers, two each, in the same order), so each slot's kit becomes the one at the same place in the new class's list (Napaco D -> Wist L), with the colour, patina, tab and the livery of the same name.
- **Main arcade set**: every event but the Deluxe pack (MAIN_EVENTS in pages.js, 50 events). The /arcade front page is the all-events leaderboard over it (summed medal times and the summed bests of everyone with a time on all 50; cumulativeBoard, shared with the category pages); the categories are in its menu.
- **Timesheets** are the arcade overview (pages.arcadeOverview(racer); /arcade and the category menu's Overview show the viewer, /timesheet [racer] anyone): `# name`, credits / backer, then events with a time over the main 50 with a stat bar, medal counts, 1st/2nd/3rd counts, the declared rival with the head to head, and a "See recent runs" menu of their 25 latest arcade runs (pages.recentSelect: place on the board now, what it took off their previous best, how long ago; picking one opens its board); the all-events leaderboard below, categories in the menu (old timesheet_<id> selects still route there).
- **Replays** (src/replays.js): runs posted in the REPLAY_CHANNEL_ID channels (comma-separated: #holo-replays, #autopilot and #speedrun; TEST_CHANNEL_ID while testing), including forwards (read from the forwarded copy; the original is fetched for its author and time), are saved through src/submit.js with a reaction: the run's emoji as the event menus show it (pages.standingEmoji for its time and place among everyone else's bests: place_1-10 when gold and top 10, else its medal, else the tick; the best of them when a post has several; the stopwatch for a staff time). YouTube links: the title must name exactly one arcade event (in English or any of the game's languages: event.names from out/loc_<culture>.json, accents ignored, Chinese/Japanese/Korean names matched without word breaks; a name two events share is dropped) and a time plausible for it (60% of gold to 1.5x bronze); the run is credited to the video's channel owner (database youtube/; a channel's first post links it to the poster, /times youtube relinks and moves its times) and dated by the earlier of upload and post; details from the YouTube Data API (YOUTUBE_API_KEY, a key in the autopilot-swgr Google Cloud project restricted to that API). Screenshots: read by an OpenAI vision model (OPENAI_API_KEY, OPENAI_MODEL default gpt-5.4-mini) into structured JSON; a results screen is identified by its three medal times (unique per event) and records its leaderboard row (the stored time, sometimes a hundredth off the SUCCESS time), an event card by the event name in it; with several rows, the racer's is the one matching their Discord names. A video file attached to a post whose text names the event and time (replays.matchClaim) is saved as video proof. Credited to the poster, or to the one person a submitter mentions; the proof is the file's own CDN link (the screenshot or video opens directly; old runs from before 2026-10-14 link the post). Those links are signed for about a day, so src/proofs.js renews every file-link proof that has expired or soon will (Discord's attachments/refresh-urls, 50 a call, works on expired ones), at start and every 6 hours (live bot only). Free OCR (Tesseract) was tried and can't read the game's fonts. Mentioning @Autopilot anywhere submits a run (replays.handleMention): the one other person mentioned is the racer (submitters only), else the author; an event and time in the text (replays.matchClaim: any time format, URLs ignored) are saved as given with the message's video, attachment or link as proof, otherwise the attachments/links (a forward's too) are read as above; the bot replies briefly without pings, with a View board button per board saved to (like podium announcements). Discord doesn't tell bots who wrote a forwarded message (and the bot can't open originals in servers it isn't in), so for a forward the mention is how the racer gets named; a run found with no racer gets the game's "?" marker (the `unknown` emoji). A forward is dated by its original's message id. A ⏱️ reaction on any message (from a submitter or the message's author) reads it the same way, crediting its poster, wherever it is (bot.js MessageReactionAdd, GuildMessageReactions intent with message/reaction/user partials). A repeat of a saved run brings in a video proof over a screenshot, never the reverse (records.isVideo), and the run keeps its earliest date. Uses the GuildMessages and Message Content (privileged) intents.
- **Join messages** (src/welcome.js): one line, the speaker's headshot (data.characterEmoji) then a random line from src/data/flavor/welcome.js (game dialogue, {user} = the new member), posted silently to WELCOME_CHANNEL_ID (TEST_CHANNEL_ID while testing).
- **Components V2**: reference pages are V2 messages (`flags: MessageFlags.IsComponentsV2`, a `ContainerBuilder` with text/sections/media/action rows; no `content` or `embeds`). Images must be attached and referenced as `attachment://name`. Limits: 40 components total, 4000 chars of text.
- **Page style**: small breadcrumb line first (`-# Arcade / Advanced`, separated by ` / `), then `# Title`. Everything in a page's header block is separated by ` / ` too (track type / vehicles / laps; variants; event track / direction / laps / conditions), never bullets or dashes. Menus stack like breadcrumbs, broadest on top, with no separator above them. A card's unlock requirement (`unlockLine`) is the last line of its header. Controls that belong to a section (e.g. tier buttons under a part's Family) sit right under that section. Don't repeat a planet's name next to its emoji.
- **Track cards** describe the track (format, vehicles, laps, variants, map) and list where it's raced by name only. Which variant, conditions and laps an event uses belong on that event's / scenario's own page (feedback: per-act appearance lists were confusing). The importer still derives campaign pools (`stop_unlock`), but cards only show which acts use a track.
- **Laps**: a loop track's header gives its lap count; scenario schedules show each race track's laps. Point-to-point tracks never mention laps. Eliminators have no laps (timed eliminations).
- **Directions**: plain Forward is implied (never written); Reverse is the `reverse` emoji; Rally is spelled out.
- **Times**: the game shows hundredths — format times to 2 decimal places (`1:19.00`).
- **Speeds**: the game shows km/h (data is stored in mph). The importer's arcade Speed formula is verified against all 53 in-game values; re-check it if the datamine changes.
- **Emojis**: use `src/data/discord/emoji.js`, which holds application emojis (they render in any server). Never reference a server's emoji directly — a menu option with an emoji the bot can't access makes Discord reject the whole message. Add new ones there and run `node src/scripts/upload-emojis.js`. Game icons (stats, parts, abilities) are generated into `assets/emoji/` by the importer, uploaded by the same script, and looked up by name with `emoji.named()` from `app-emoji.json`.
- **Private replies**: use `flags: MessageFlags.Ephemeral`; the `ephemeral: true` option is deprecated in discord.js.
- **/search must cover everything**: every new kind of reference page (vehicles, parts, characters, campaign...) gets an entry in `KINDS` in `src/swgr/search.js` in the same change that adds the page.
- After adding or changing a command's `data`, re-run `npm run deploy -- --guild` (test) or `--global` (live).
